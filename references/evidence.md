# 证据与二次验证

## 两维标注

每条重要结论同时标确认状态与结论性质：

|维度|值|定义|
|---|---|---|
|确认状态|已经明确确认|直接证据支持结论的具体范围|
|确认状态|待确认核实|存在推断、缺证、冲突或版本不明|
|结论性质|页面事实|页面、实际产物或提供材料直接可见|
|结论性质|合理推断|依据事实推导，写出依据及替代解释|
|结论性质|尚未确认|材料不足以支持判断|

合理推断和尚未确认默认均待核实。补证后重写结论及标签并保留验证记录；部分支持不代表整条推断已确认。

“官方声明支持功能”只证明官方作出该声明，不证明功能稳定可用；演示也仅证明演示内行为。失去原始出处的笔记注明用户材料记载，不能称官方原文。旧截图价格不当作当前价格。

## 证据索引

|证据编号|来源类型|标题/步骤|URL或附件路径|采集日期|版本/发布日期|视频时间点|直接可见内容|限制|
|---|---|---|---|---|---|---|---|---|

来源类型区分亲自实测、官方文档、官方演示、第三方演示、用户材料。编号如 E001，关联结论 C001。网页逐步截图，视频记录时间区间。保留失败证据。AI 说已完成要验收产物；AI 说官方写了要核对原文。

## 二次验证队列

|问题编号|待核实结论/冲突|影响|已有依据|需要补证|验证动作|验证结果|更新后状态|
|---|---|---|---|---|---|---|---|

1. 优先验证会改变核心判断的问题。
2. 找直接证据：原始页面、实际产物、完整演示和明确官方文档。多篇转载同一出处不算独立验证。
3. 对架构用不同任务、局部修改等观察行为；对计费核对前后余额与官方规则，不通过未授权支付验证。
4. 冲突先检查版本、地区、套餐、模式和时间差异，不择一忽略。
5. 一轮有针对性的补证后仍不确定，记录原因与所需最小补充材料；新证据出现再继续，不无限搜索。

## 示例

- 【已经明确确认】【页面事实】E001 显示编剧与分镜师两个角色。
- 【待确认核实】【合理推断】可能存在多 Agent 编排，也可能由固定流程模拟，需执行记录补证。
- 【待确认核实】【尚未确认】缺少失败规则和余额记录，不知道失败是否退积分。
- 【已经明确确认】【页面事实】截图显示反复回复、流程未推进；“状态更新失败”属于另行待验证的原因假设。
