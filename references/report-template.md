# 报告模板

按复杂度调整篇幅，不要求填满未知信息。每章分列已确认与待核实结论，并附确认状态、结论性质和证据编号。主结论先行，保留必要证据链。

## 1. 拆解范围与核心判断

产品、入口、类型、版本/地区/套餐、日期、代表性任务、取证方式、覆盖范围、价值判断、交付结果和关键限制。

## 2. 产品与市场定位

一句话定位，B 端使用者/买单者/验收者，痛点、替代方案、竞争格局、差异化。市场数字保留时间与出处，区分官方主张与分析判断。

## 3. 测试方案与能力评估

|任务与输入|预期结果|验收标准|实际结果|耗时/重试/人工干预|证据|
|---|---|---|---|---|---|

同时评估端到端效果和过程能力。评分另附权重、锚点、样本、计算；未测不打分。

## 5. 人机分工与技术

|步骤|AI 职责|人类职责|工具|确认机制|为什么需要人|证据|
|---|---|---|---|---|---|---|

架构类型、依据和适用模式，技术流程图；按需附单 Agent、上下文、状态与实现假设。

## 6. 模型、收费与成本

|AI 步骤|模态|模型/档位|自研或外接|可替换性/路由依据|证据与状态|
|---|---|---|---|---|---|

|收费机制|套餐与期限|单次消耗|失败/重试规则|价格日期与来源|
|---|---|---|---|---|

实际成本估算单列公式、假设、单位、区间和来源；否则写成本未知。

## 7. 基础能力与壁垒

|能力/资产|可购买或复制部分|难复制部分|独占性与积累机制|壁垒判断|证据与限制|
|---|---|---|---|---|---|

## 8. 五层架构总图

用户需求场景、用户层、技术层、模型层、基础层。框内简短名词，标证据类别与编号，推断连线明确区分；附场景、旅程、AI 步骤、模型与资产的文字对应。

## 9. 优势、问题与改进

|设计或可观察问题|用户价值/影响|原因假设|建议与优先级|验证方式|证据|
|---|---|---|---|---|---|

对照完整性：定位、正向交付、异常恢复、人机边界、消耗透明度、基础资产积累。

## 10. 证据与二次验证

按 evidence.md 附证据索引、验证动作、更新结论与未解决项。关键限制同时出现在相关正文。

## 格式适配

Markdown 和 HTML 的本地图片随报告交付，使用真实相对路径。视频标来源与时间点。HTML 确认状态同时使用文字，截图可放大，窄屏表格可滚动，图形有文字解释。飞书保留结构，按可用能力写入与回读；无法写入时交付 Markdown 与附件并明确状态。

## 方法来源与边界

依据用户确认的五层五问方法、产品类型分流和二次验证要求，及用户提供《以 OiiOii 为例拆解一个 Multi Agent 平台》案例整理。公开方法页：https://w3d1.vercel.app/ 。两份飞书链接在编写时未读到正文，不声称已完成核对；本地案例是用户补充材料。

案例中的模型、价格、市场数字、评分和实现推导不作为通用事实库；实际任务重新研究。本技能无需原网页或用户机器上的案例路径即可运行。
